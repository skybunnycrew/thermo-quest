SET UP THE CLASS SERVER About five minutes, free, no coding. The server just relays chat and positions between students' browsers.
1 Go to supabase.com, click Start your project and sign up with GitHub or email. The free plan is plenty.
2 New project: name it thermo-quest, set any database password (you will not need it here), pick the region nearest your school, Create. Wait about a minute.
3 Left sidebar → Project Settings (gear). Data API shows the Project URL. API Keys shows the key: copy the one labelled publishable (or the legacy anon public key; either works).
4 Open multiplayer-config.js, the small file next to this game, in any text editor. Paste the URL and the key between the quotes. Change TEACHER_PASSWORD from entropy. Save.
5 Saved chat history: left sidebar → SQL Editor → New query, paste the block below, Run. Skip this and chat still works; it just starts empty each visit.
6 Put the four game files on any web host or shared drive and send students the link. Everyone who opens it shares one world. Reload: the dot up top turns green.
SQL FOR STEP 5
create table if not exists public.messages ( id bigint generated always as identity primary key, created_at timestamptz not null default now(), room text not null, name text not null default '', body text not null default '', kind text not null default 'chat' ); alter table public.messages enable row level security; create policy "class can read" on public.messages for select to anon, authenticated using (true); create policy "class can post" on public.messages for insert to anon, authenticated with check (char_length(body) <= 200); create index if not exists messages_room_time on public.messages (room, created_at desc);
The teacher password lives in that config file, so anyone who reads the file can find it. Fine for a classroom; not a vault.
